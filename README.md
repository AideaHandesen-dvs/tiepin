# tiepin

小さな OLED で **DVD スクリーンセーバー**（あの跳ね回るロゴ）を動かす、ネクタイピンサイズのお遊びガジェット。
"DVD" のロゴが画面を跳ね、**四隅にピタッと同時に当たった瞬間だけ**白黒が反転する ―― 俗に言う「角待ち」。

スマホ（Android の Chrome）から Bluetooth で、表示の切り替え・流す文字・アイコン・ライフゲームまで操作できる。

![tiepin demo](demo.gif)

## 構成
- **MCU** … ESP32-C3 SuperMini（RISC-V）
- **表示** … SH1107 128×64 OLED（I2C・単色）
- **ライブラリ** … [U8g2](https://github.com/olikraus/u8g2)・Arduino core 付属の `BLE`

## 配線（I2C）
| OLED | ESP32-C3 |
|:---:|:---:|
| SDA | GPIO8 |
| SCL | GPIO9 |
| VCC | 3V3 |
| GND | GND |

## ビルド / 書き込み（PlatformIO）
```sh
pio run -t upload
```
ESP32 を何台も挿している机では、口を名前で指す（`/dev/ttyACM*` の番号は挿し直すと変わる）：
```sh
pio run -t upload --upload-port /dev/serial/by-id/usb-Espressif_USB_JTAG_serial_debug_unit_<MAC>-if00
```
確かめた組み合わせ：PlatformIO の `espressif32` 8.0.0（Arduino core の BLE は 3.3.12）。

## 表示
| 表示 | 中身 |
|---|---|
| **跳ねる** | DVD スクリーンセーバー。跳ねる文字（初期値 "DVD"）・当たり判定の幅・速さを変えられる。角に入ると白黒反転 |
| **文字** | 好きな文字を出す。画面に収まれば真ん中に止め、収まらなければ右から左へ流す |
| **時計** | 時:分。`:` が 1 秒ごとに点滅。時刻はつないだ時にスマホから受け取る |
| **ライフ** | ライフゲーム。ランダムにまいて育て、落ち着いたら勝手にまき直す |

選んだ表示・文字・跳ねる文字・幅・速さは本体の NVS に覚える＝電源を切っても残る。
時刻だけは覚えない（RTC が無い）ので、電源を入れ直したらもう一度つなぐ。

## スマホから操作（Bluetooth）
操作ページ：**https://aideahandesen-dvs.github.io/tiepin/** （中身は [`docs/index.html`](docs/index.html)）

1. **Android の Chrome** で開く（iPhone の Safari は Web Bluetooth が無いので動かない）
2. スマホの Bluetooth と**位置情報**をオンにする（Android の Chrome は位置情報がオフだと機器を探せない）
3. 「tiepin につなぐ」を押して、一覧から `tiepin` を選ぶ

つなぐと本体の今の設定を読んでページに映し、スマホの時刻を本体へ送る。
一覧に出ない時は「近くの機器を全部出して選ぶ」で、本体が電波を出しているかを見分けられる。
本体はつながっている間も名乗り続けるので、前のつながりが裏で残っていてもつなぎ直せる。

Web Bluetooth は https でしか動かないので、ページは GitHub Pages（`main` の `/docs`）で公開している。

### ライフゲーム
- 盤は画面の 128×64 の点そのまま。**端は反対側とつながる**（トーラス）＝右へ出たグライダーは左から戻る
- 3 割くらいをランダムにまき、1 コマ（約 33ms）で 1 世代進む
- **全滅**・**同じ盤の繰り返し**（周期 8 まで）・**300 世代で生きているマスの数の増減が 12 以内**のどれかで「落ち着いた」と見て、3 秒見せてからまき直す。パソコンで 12 回回して、25〜144 秒でまき直すのを確かめた
- ページの「ライフ」をもう一度押してもまき直す

## BLE の口
サービス `7e1a0001-6a3d-4c1b-9e57-71e9e0c0de01`、名前 `tiepin`。キャラクタリスティックは末尾 `…-71e9e0c0de01` 共通で、頭だけ違う：

| UUID の頭 | 読み書き | 中身 |
|---|---|---|
| `7e1a0002` MODE | 読・書 | 1 バイト：0=跳ねる 1=文字 2=時計 3=ライフ（ライフ中にもう一度 3 でまき直す） |
| `7e1a0003` TEXT | 読・書 | 流す文字。UTF-8・最大 96 バイト |
| `7e1a0004` SPEED | 読・書 | 2 バイト：跳ねる速さ dx, dy（1〜6） |
| `7e1a0005` TIME | 書 | 8 バイト：UNIX 秒（int32 LE）＋ UTC からの分（int32 LE） |
| `7e1a0006` LOGO | 読・書 | 跳ねる文字。UTF-8・最大 32 バイト |
| `7e1a0007` BOX | 読・書 | 書く 1 バイト：当たり判定の幅（8〜120・0＝文字に合わせる）。読む 3 バイト：幅の設定・実際の幅・実際の高さ |

BLE の書き込みは BLE の糸で届くので、文字や箱の決め直し・NVS への保存は描く糸（`loop`）で行う。

## 「角待ち」は報われるのか？
`dx=2, dy=1`・盤面 128×64 だと、横の壁は **48コマ**・縦の壁は **50コマ**ごとに当たる。
両方が同時に当たる（＝角に入る）のは **lcm(48, 50) = 1200 コマ ≒ 40秒に1度**。
`dx`/`dy` を変えれば周期も変わり、**一生角に当たらない設定**すら作れる。
当たり判定の幅を変えても周期は変わる。ページは本体と同じ計算で「角に入るのは何秒に 1 度か」を出す。

## つまずいた所
- **外付けの NimBLE-Arduino は使わない**：`h2zero/NimBLE-Arduino 1.4.3` は今の Arduino core が抱える NimBLE と食い違い、起動のたびに `esp_bt_controller_init` の中で Guru Meditation → 再起動を繰り返した（画面も真っ白のまま）。core 付属の `BLE` に替えて直った
- **画面が真っ白なら、まずシリアルを読む**：`setup()` が終わるまで画面には何も描かれない。落ちた理由（`rst:` の行と Guru Meditation のアドレス）はシリアルに出るので、アドレスは `riscv32-esp-elf-addr2line -pfiaC -e .pio/build/esp32-c3-devkitm-1/firmware.elf <アドレス>` で関数名に直せる
